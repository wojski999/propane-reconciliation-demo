# Preserve the delivery gates through orchestration

Date: 2026-11-05.

The demo's fixture chronology and refund-capacity reviews repeatedly found
realistic adversarial cases despite 100% measured coverage. Keep independent
hand-computed oracles, negative mutation probes and a reviewer who derives the
answer from inputs. Coverage proves exercised code, not correct financial policy.

Two integration failures in the native issue #9 workflow required explicit checks:
its PR node published the raw task instead of the prepared business description,
and omitted SDLC labels. The parent read back and repaired the title/body/labels
before the merge gate. Reuse the installed om-open-pr normalization and tracker
readback for subsequent runs rather than adding another competing PR mechanism.

An observer script failed at startup because multiline literals were not escaped.
The parent discovered it at the next check, compiled the repaired script before
launch, verified the PID and empty error log, and retained bounded rechecks.
A launched process is not proof that a watcher is operational.

Record each reviewed SHA and distinguish documentation-only follow-up commits
from application changes. Do not reuse QA after an unreviewed code push. Native
human gates require an explicit owner answer; implementation approval does not
justify silently bypassing the selected workflow's gate.

Keep live optional text outside deterministic calculations. Provider failures,
unsupported citations and stale illustrative digests must preserve computed
artifacts and make fallback visible. Default and CI stay offline.
